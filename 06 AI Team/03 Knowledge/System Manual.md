# System Manual

How this vault is organised, what each note type carries, and the rules the pipeline never breaks.

## Rooms

| Room | Holds |
|---|---|
| `00 Home` | `Home.md` (dashboard), `Settings.md` (defaults), `Pipeline.base`, `Reviews.base` |
| `01 Queue` | one root `yt2b-queue` note per video request, plus the read-only discovery boundary under `Discovery/` |
| `02 Videos` | one run folder per video: `run.md`, `source/`, `analysis/`, `brief/`, `strategy.md` |
| `03 Blogs` | one delivery folder per article; also the Writing Studio project |
| `04 Approvals` | `policy.md` and `queue/` with one `yt2b-approval` note per decision |
| `05 Evaluations` | one `yt2b-evaluation` note per article, plus `pipeline-rubric.md` |
| `06 AI Team` | `01 Agents`, `02 Sessions`, `03 Knowledge` (`01 Guidelines`, `02 SOPs`, `03 Scripts`, `04 Voice`, `05 Learnings`, this manual) |
| `_alembic` | Writers Alembic workflows generated by `alembic_sync.py` |
| `_templates` | one template per note type the pipeline writes |
| `_system` | `plugin-lock.json`, `tag-taxonomy.json`, `settings-schema.json` |
| `_assets` | Obsidian attachments, created by Obsidian on first use |
| `skills/youtube-to-blog` | the skill: `SKILL.md`, `scripts/`, `references/`, `tests/` |
| `agents` | `yt2b-analyst.md`, `yt2b-strategist.md`, linked from `.claude/agents` |
| `.cache/video` | downloaded videos, hidden from Obsidian and git |

## Note types and properties

Every pipeline note carries `type`, `created` and `updated` (YYYY-MM-DD). Operational notes use `tags` with `yt2b` first. Publishable `yt2b-blog` notes are the exception: their `tags` are public topic taxonomy only, while their typed fields carry pipeline state. Frontmatter stays flat: scalars and lists, no nested maps.

- `yt2b-queue` (`01 Queue/<date>-<id>.md`): `video_url`, `video_id`, `rights` (own, third-party, ask), `mode` (companion, expand), `priority`, `status`, `run`, `note`, `source_notes`, `discovered_via`.
- `yt2b-source` (`01 Queue/Discovery/Saved/*.md`): source material saved from RSS Dashboard with `source_url`, `feed`, `published`, `status`, `queue` and provenance tags. It is untrusted research material, not a pipeline request.
- `yt2b-video` (`02 Videos/<run>/run.md`): `video_id`, `video_url`, `title`, `channel`, `channel_url`, `published`, `duration_s`, `rights`, `mode`, `status`, `captions` (manual, auto, whisper, none), `blogs`, `queue`. Body: Summary, Key takeaways, Tags, Artifacts, Log.
- `yt2b-blog` (`03 Blogs/<date> <slug>/<slug>.md`): post fields `title`, `description`, `date`, `author`, `slug`, `tags`, `lang` (optional `canonical`, `kicker`, `og_image_alt`); pipeline fields `yt2b_status`, `yt2b_score`, `yt2b_video`, `yt2b_rights`, `yt2b_mode`, `yt2b_template`; Writing Studio fields `binder-order`, `binder-status`, `binder-type`, `word-count-goal`.
- `yt2b-approval` (`04 Approvals/queue/<date>-<id>-<kind>.md`): `kind` (strategy, outline, image), `status`, `run`, `blog`, `requested`, `decided`, `expires`, `selected`, `cost_estimate`. Body: Request, Options (task list `- [ ] id: label`), Questions (`answer:` lines), Decision.
- `yt2b-evaluation` (`05 Evaluations/<date>-<slug>.md`): `blog`, `run`, `score`, `blocking`, `p0`, `gates_passed`, `overlap_ratio`, `frames_in_place`, `attribution_ok`, `links_ok`, `voice_flags`. Body: scorecard tables and findings by severity.
- `yt2b-agent` (`06 AI Team/01 Agents/<name>.md`): `name`, `role`, `source`, `tools`, `stage`, `dispatch`. Body: Mission, Owns, Never, Inputs, Outputs.
- `yt2b-session` (`06 AI Team/02 Sessions/`): handoff notes; Agent Client exports carry the plugin's own frontmatter.
- `yt2b-knowledge` and `yt2b-learning`: `title`, `kind` (guideline, sop, script, voice, learning, manual).
- `yt2b-settings` (`00 Home/Settings.md`): the thirteen defaults, explained in the note and typed in `_system/settings-schema.json`.

## State machine

- Queue note: `queued` > `running` > `done` or `failed`.
- Run note: `fetched` > `analyzed` > `briefed` > `strategy` > `writing` > `done`, or `blocked` from any stage. Every transition appends a timestamped line to `## Log` in `run.md`.
- Blog note: `drafting` > `drafted` > `reviewed` (score 90 or more and not blocking) or `blocked`; `published` is set by a human after publishing from Writing Studio.
- Approval note: `requested` > `approved`, `declined` or `expired`.

## Where every artifact lives

- Run folder `02 Videos/<date>-<slug40>-<videoId>/`: `source/video.info.json`, `source/captions.<lang>.vtt`, `source/thumbnail.jpg`; `analysis/avt_outputs/<id>/` (video-analyzer output, kept untouched), `analysis/segments.json`, `analysis/transcript.md`; `brief/<slug>-brief.md`, `brief/video-brief.json`; `strategy.md`.
- Blog folder `03 Blogs/<date> <slug>/`: `<slug>.md`, `<slug>.html`, `<slug>.pdf`, `hero.jpg` or `hero.png`, `hero-credit.txt`, `images/` (frames, `video-thumb.jpg`, `CREDITS.txt`, `manifest.json`), `.render/` (temporary), `preview/`, `review.md`, `capabilities.json`, `preflight-report.json`, `publish-kit/` (`embed.html`, `video-object.jsonld`, `layouts.css`, `<slug>.publish.md`, `youtube-chapters.txt` for own videos, `README.txt`).
- Video file: `.cache/video/<id>.mp4`, deleted after the last approved blog unless `keep_video` is true.
- Voice: `BRAND.md` and `VOICE.md` at the vault root (read by claude-blog through `load_untrusted_root.py`), the Author Profile in `06 AI Team/03 Knowledge/04 Voice`.

## Bases

- `00 Home/Pipeline.base`: views Queue (`type == "yt2b-queue"`), Videos (`yt2b-video`), Blogs (`yt2b-blog`).
- `00 Home/Reviews.base`: views Approvals (`yt2b-approval`), Evaluations (`yt2b-evaluation`).
- `01 Queue/Discovery/Sources.base`: saved source notes only (`yt2b-source`), linked from Home and the Discovery hub.

Both exclude `_templates` and sort newest first. Home embeds one view per section with `![[00 Home/Pipeline.base#Queue]]`. No Dataview is used anywhere.

Versions, sources and file hashes are pinned in `_system/plugin-lock.json`; the ids are listed in `.obsidian/community-plugins.json`.

RSS Dashboard is built from pinned upstream source with `plugins/rss-dashboard-safe-save.patch`. The patch refuses same-title collisions instead of trashing existing notes and JSON-quotes remote metadata before YAML insertion. On a new synced device, let the first vault sync finish before enabling RSS Dashboard. See [[06 AI Team/03 Knowledge/02 SOPs/Discover and queue sources|Discover and queue sources]].

The vault-local `youtubetoblog-home` plugin owns both startup surfaces. Empty main tabs become the central capture dashboard. The active left tab becomes the compact YouTube to Blog sidebar with New chat, discovery, pipeline rooms and live counts. **Queue open source** promotes the currently open saved YouTube source and writes links in both directions. Writing Studio is linked from the bottom of the sidebar and does not open automatically.

## The skill and the agents

`skills/youtube-to-blog/SKILL.md` is the orchestrator (`/youtube-to-blog setup | doctor | queue add | analyze | strategy | write | full | status`). Scripts are deterministic and print exactly one JSON object; agents make the judgment calls:

- `yt2b-analyst` (segments to brief) and `yt2b-strategist` (brief to angles and approval note) live in `agents/`.
- `blog-researcher`, `blog-writer`, `blog-seo` and `blog-reviewer` come from claude-blog and are used as they are.
- `visual-architect` and `visual-critic` come from Banana Claude when that plugin is enabled.

Each agent has a note in `06 AI Team/01 Agents`; `agent-index.md` maps stages to agents. One note per script lives in `06 AI Team/03 Knowledge/03 Scripts`.

## Approval rule

Strategy, outline and paid image steps stop at a note in `04 Approvals/queue`. Work continues only when that note's `status` property is `approved`. Ticked option boxes select what to build; they do not grant approval by themselves. `--auto` lets the pipeline approve the recommended angle and records that in the note. Approvals carry an `expires` time; a declined or expired approval leaves the run at `strategy`.

## Evaluation rule

Every delivered article gets an evaluation note. It passes when the reviewer score is 90 or more, there are zero P0 findings, `review.md` ends with `BLOCKING: false`, every preflight gate passed, and the pipeline checks hold: transcript overlap under the rubric threshold, frames placed in their sections, attribution and disclosure present, every video link in `www.youtube.com/watch?v=` form, no voice taboo phrases. Thresholds live in `05 Evaluations/pipeline-rubric.md`. A failing article is `blocked`, the run is `blocked`, and a learning note is added to `06 AI Team/03 Knowledge/05 Learnings`.
