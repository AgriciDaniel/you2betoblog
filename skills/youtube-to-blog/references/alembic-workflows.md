# Writers Alembic workflows (YT2B set)

Writers Alembic 1.2.3 runs an AI workflow on the current selection or on the whole note. Workflows are markdown files in `_alembic/` (the plugin's default folder). The YT2B set is generated by `scripts/alembic_sync.py` from `references/alembic/*.md` with the author's `VOICE.md` and `BRAND.md` embedded in the system prompts, so every pass writes in the author's voice. Before `setup` runs, the same files carry a neutral voice.

## Catalogue

| Workflow | id | Input | Output | Use it when |
|---|---|---|---|---|
| YT2B Rewrite in my voice | `yt2b-rewrite-in-my-voice` | selection | replaces, then a humanize pass | a passage reads generic or off-voice |
| YT2B Tighten this section | `yt2b-tighten-section` | selection | replaces | a section runs long, cuts 20 to 35 percent |
| YT2B Answer-first intro | `yt2b-answer-first-intro` | selection (the intro) | replaces | the intro warms up instead of answering |
| YT2B Attribute claims to the creator | `yt2b-attribute-claims` | selection | replaces | video claims lack "creator shows at [mm:ss]" |
| YT2B Key Takeaways box | `yt2b-key-takeaways` | whole note | inserts at the cursor | the draft is stable; cursor after the intro |
| YT2B Meta description | `yt2b-meta-description` | whole note | inserts at the cursor | cursor at the end of the `description:` line in source mode |
| YT2B FAQ from this note | `yt2b-faq-from-context` | whole note | inserts at the cursor | readers ask real questions the note answers |
| YT2B Alt text for this image | `yt2b-alt-text` | selection (one image line) | replaces | after frames are placed |
| YT2B De-slop | `yt2b-de-slop` | selection | replaces | padding, vacuous claims, vague attribution, residue |
| YT2B Section from transcript excerpt | `yt2b-section-from-transcript` | selection (transcript excerpt) | inserts below the selection | expanding a section in expand mode |
| YT2B Fact-check flags | `yt2b-fact-check-flags` | selection | replaces with `[VERIFY: ...]` markers | before the reviewer runs |

Suggested order for a polishing pass: Fact-check flags, Attribute claims, De-slop, Tighten, Rewrite in my voice (only where needed), Answer-first intro, Key Takeaways, FAQ, Alt text, Meta description. Each run is one `claude --print` call; keep selections under about 600 words. For a transcript section, copy the excerpt from `analysis/transcript.md` into the draft, select it, run the workflow, then delete the excerpt.

## Provider setup (Claude CLI, no API key)

1. Enable Writers Alembic. Settings, Writers Alembic, Providers: the default profile `default-claude-cli` runs `claude --print` with the logged-in CLI. The templates reference that id; do not rename it.
2. Log in once in a terminal (`claude`).
3. Flatpak Obsidian (this machine, `md.obsidian.Obsidian` 1.13.7): the sandbox PATH is `/usr/bin:/app/bin:...` and `claude` lives in `~/.local/bin`. The native binary runs inside the sandbox (verified: `flatpak run --command=$HOME/.local/bin/claude md.obsidian.Obsidian --version` prints 2.1.259), so only the PATH is missing. Either set the command path in the provider settings if the plugin offers one, or add a user override and restart Obsidian: `flatpak override --user --env=PATH="$HOME/.local/bin:/usr/bin:/app/bin" md.obsidian.Obsidian`. The override is the user's decision; record the result in `references/delivery.md` ("Alembic Claude CLI provider with Claude Code 2.1.x").
4. Workflows folder: keep the default `_alembic`; `alembic_sync.py` always writes there.

## Running

- Command palette: `Writers Alembic: Run workflow` opens the picker; each workflow also has its own command `Writers Alembic: YT2B ...`.
- Hotkeys: Settings, Hotkeys, search "YT2B". Suggested: `Ctrl+Alt+V` Rewrite in my voice, `Ctrl+Alt+T` Tighten, `Ctrl+Alt+A` Attribute claims, `Ctrl+Alt+K` Key Takeaways, `Ctrl+Alt+F` Fact-check flags, `Ctrl+Alt+D` De-slop. Check for collisions with other plugins.
- Undo: `Ctrl+Z` reverts a replacement or an insert.
- `linkDepth` is 0 on every YT2B workflow so wikilinks in the note are not expanded into the prompt (run notes and transcripts are large).

## Editing and syncing

- Edit any `_alembic/yt2b-*.md` freely. `alembic_sync.py` compares the file with its `yt2b_hash` and keeps an edited file (listed under `skipped`); `--force` replaces it with the template render.
- A new `VOICE.md` or `BRAND.md` needs one sync run: pristine workflows are refreshed, edited ones reported.
- New workflow: add `references/alembic/<id>.md` with `id: yt2b-<id>`, `yt2b_id: <id>`, the Alembic keys and a body under 40 lines, then sync. Files in `_alembic/` without the `yt2b-` prefix are yours and never touched.
- Placeholders: `{{VOICE}}` is the `VOICE.md` body (H1 and auto-load line removed), `{{BRAND}}` the `BRAND.md` body; the neutral fallback text lives in `alembic_sync.py`.

## Limits

- Only Rewrite in my voice sets `humanize: true`; a second pass can flatten specifics, so read the result.
- The workflows never add facts; they flag or attribute. Fill every `[mm:ss]` and resolve every `[VERIFY: ...]` before the reviewer runs; the reviewer treats them as unresolved placeholders.
- After polishing, delivery must run again for `<slug>.html` and `<slug>.pdf` (see `references/writing-studio.md`).
